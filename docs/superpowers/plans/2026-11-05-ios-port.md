# Folia iOS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Port upstream Folia to a bundled iOS app, targeting complete music functionality including Spotify and tracking remaining desktop replacements honestly.
**Architecture:** Capacitor host + Swift filesystem/settings bridges + existing Omni provider adapters with runtime-configurable transports.
**Tech Stack:** React/TypeScript/Vite, Capacitor 6.2.1, Swift/UIKit, GitHub Actions macOS.
**Spec:** docs/superpowers/specs/2026-11-05-ios-port-design.md

## Global Constraints
- iOS 16.0 minimum; arm64; no unnecessary private entitlements.
- All providers and lyric styles stay present. Actual backend URLs are configured on device.
- No embedded secrets; local music never uploaded.
- No fabricated build/device/feature validation.

## Review Focus
- Invalid backend URLs, malformed responses and unavailable gateways must fail clearly.
- Native paths must stay inside the imported-music directory; symlinks and traversal rejected.
- Directory handles must survive IndexedDB serialization and application restart.
- Partial/cancelled imports must not leave a registered broken library.
- Swift/device compilation, iOS 16 WebKit rendering and protected streaming cannot be validated on this Linux host.

### Task 1: iOS host and repeatable build
- [ ] Pin Capacitor 6.2.1; create native iOS project and configure iOS 16, arm64, all orientations, audio background mode.
- [ ] Build Vite targeting Safari 16; add build/prepare/sign/package scripts and macOS Actions workflow.
- [ ] Verify configuration and web build; native build requires a user-owned GitHub fork or Mac.

### Task 2: Runtime backend configuration
- [ ] Add native persisted endpoint editor and TypeScript config types/URL validation tests.
- [ ] Wire runtime NetEase/QQ/KuGou addresses into existing transports.
- [ ] Add explicit remote operation transport, validation/timeout tests, and wire Spotify/YouTube/Bodian/Qishui availability and requests without creating a fake Electron bridge.
- [ ] Document exact gateway contract; do not infer that existing compatible APIs include this extra gateway.

### Task 3: Persistent native local music
- [ ] Implement native folder picker, sandbox copy, validated directory listing, and file resolution.
- [ ] Add FileSystem-compatible read handles with tested DTO serialization/hydration and db integration.
- [ ] Check cancellation, persistence, and traversal guards.

### Task 4: Appearance and native lifecycle
- [ ] Respect existing theme preferences; default first iOS launch to system appearance.
- [ ] Apply safe areas and landscape viewport compatibility; enable playback AVAudioSession.
- [ ] Retain upstream media-session behavior; test physically before asserting background reliability.

### Task 5: Validation and handoff
- [ ] Run typecheck, targeted tests and production web build; inspect source diff.
- [ ] Independent review of the complete patch and correction of confirmed findings.
- [ ] Persist source/checkpoint with exact upstream revision and unresolved capabilities.
- [ ] Request backend details and a writable fork only when needed for actual remote build/integration.

## Deferred until dependency information/device build is available
- Real backend authentication/Spotify audio tests require supplied endpoints and compatible gateway.
- Desktop FFmpeg export, Node mod host, HiFi/AI engines, wallpaper/desktop windows and Apple Music native playback remain separate migrations. Preserving their source is not implementing them on iOS.
